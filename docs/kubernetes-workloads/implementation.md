# Tracked Runtime Implementation

This document describes tracked repository source. It does not establish that any stack is deployed, healthy, or configured the same way in a live cluster.

## Workload Metadata

[`withWorkloadLabels`](../../src/types.ts) is a Pulumi resource transformation used by many components and modules. When labels are supplied, it merges them into Kubernetes resource metadata and into pod templates for Deployments, StatefulSets, DaemonSets, ReplicaSets, Jobs, and CronJobs. Existing resource labels take precedence. When labels are omitted, the helper leaves resource options unchanged.

Stack configuration commonly supplies the five `app.kubernetes.io/*` identity labels and `rholden.dev/workload-layer`. Coverage is not universal; see [verification](verification.md).

The planned reboot implementation in [`scripts/planned-node-reboot.sh`](../../scripts/planned-node-reboot.sh) selects labeled, non-storage pods by default.

## Model Gateway

[`programs/agent-gateway`](../../programs/agent-gateway) is a Pantheon-configured Pulumi program separate from ingress. Tracked desired source unconditionally creates standalone Agent Gateway v1.5.0. It does not create the Kubernetes controller, Agent Gateway CRDs, GatewayClass, Gateway, `agentgateway.dev` Backends, or policies. The v1.5 runtime preserves normalized token accounting, including prompt-cache tokens, without a legacy compatibility override.

[`src/components/agent-gateway.ts`](../../src/components/agent-gateway.ts) requires one of three route-storage states. `file` renders Helm `readonly` mode with ten final file routes and no database route set. `prepare-database` renders Helm `database` mode with the final file routes plus ten equivalent database routes prefixed `pulumi-migration-`. `database` retains Helm `database` mode with no file routes and the final legacy route set selected by the representation mode: ten routes except for Bifrost only under `first-class`. Source supports only the forward sequence `file -> prepare-database -> database`. The parser rejects the removed `prepare-file` mode; reverse route-storage migration has no supported workflow.

Pantheon tracked configuration currently selects `routeStorageMode: database` and `routingRepresentationMode: first-class`. The resulting desired startup configuration retains the process addresses, PostgreSQL environment placeholder, tracing, one `default` listener on port `4000`, body `model` extraction into `x-model` with the audio and UI/API exclusions, and UI attachment, but contains no file-backed legacy routes. It adds file-owned first-class LLM attachment with gateway `default` and an empty model list. Its `llm.policies.apiKey` uses `mode: permissive` and `keys: []`. A separate `600s` timeout policy targets internal route `internal/llm:request`. The fronting Gateway API HTTPRoute also sets its request timeout to `600s`, preventing the private kgateway edge from applying its shorter default to streaming responses. [`src/components/agent-gateway.test.ts`](../../src/components/agent-gateway.test.ts) covers all route-storage and routing-representation states, generated resources, credential placeholders, protected database configuration, normalized chart resources, and the fronting timeout. The Pulumi component has logical name `agent-gateway` and token `homelab:components:AgentGateway`. The chart configures two replicas, a PodDisruptionBudget with `maxUnavailable: 1`, and a `660s` pod termination grace period. Its connection termination deadline remains `600s`.

The component creates Secret `agent-gateway-env`; Helm chart child `agent-gateway-chart`; Helm release and fullname `agent-gateway`; ConfigMap `agent-gateway-config`; and ServiceAccount, Service, Deployment, PodDisruptionBudget, and HTTPRoute all named `agent-gateway`. Those Kubernetes resources are in `agentgateway-system`. The Service exposes the normal gateway and UI on port `4000`; HTTPRoute `agent-gateway` attaches to `ingress/default-gateway` and targets Service `agent-gateway:4000`.

The component binds debug administration to `127.0.0.1:15000`, metrics to port `15020`, and readiness to port `15021`. Its metrics instance annotation is `agent-gateway`, and workload labels and selectors use name and instance `agent-gateway` with component `llm-gateway`. It configures OTLP gRPC tracing to `telemetry.holdenitdown.net:4317`. It does not create the Kubernetes UI Service or its dedicated `/config_dump` route. The normal UI and configuration API share the production Service and are reachable only through the private Agent Gateway hostname. Raw `/api/config` remains a read-only view of the file-backed bootstrap; persistent UI changes use `/api/config/resources/*`.

The file-owned API key policy applies in `prepare-first-class` and `first-class`. Legacy-only `routes` mode retains its prior bootstrap without this policy. The empty file key list permits runtime PostgreSQL keys; it does not declare an empty desired runtime collection. Pulumi creates no `llm.apiKey` resource set and does not reconcile or delete runtime keys. The nine providers, eighteen Pantheon models, and Bifrost legacy route retain their current contracts.

Self-service clients use `PUT https://agent-gateway.holdenitdown.net/api/config/resources/llm.apiKey` with `resources: [{value: {keyHash, metadata}}]`. The `keyHash` format is `sha256:<64 hexadecimal digits>`; clients retain the raw key locally. Metadata uses `name: opencode:<repo>`, `user: rfhold`, and `group: <repo>`. Clients omit resource IDs; Agent Gateway assigns UUIDs and reserved metadata. Repository attribution uses `group`, with no budgets or model restrictions.

The pinned [v1.5.0 API key source](https://github.com/agentgateway/agentgateway/blob/v1.5.0/crates/agentgateway/src/http/apikey.rs) defines the hash format and permissive semantics. Missing or invalid keys pass; valid keys supply metadata claims. `optional` mode rejects invalid placeholders, so it does not preserve open-client behavior. The [v1.5.0 configuration store](https://github.com/agentgateway/agentgateway/blob/v1.5.0/crates/agentgateway/src/config_store.rs) appends database keys to `llm.policies.apiKey.keys`. It rejects database keys without that policy and assigns UUIDs for collection creation. The [pinned chart helper](https://github.com/agentgateway/agentgateway/blob/v1.5.0/controller/install/helm/agentgateway-standalone/templates/_helpers.tpl) preserves the supplied LLM configuration. Chart `database` mode sets `config.storage.mode: hybrid` and the PostgreSQL connection.

The private local network defines trust for the unauthenticated self-service configuration API. Permissive key validation provides attribution, not access control; self-service metadata does not verify identity. Source adds no endpoint or network exposure. This LLM policy does not cover Bifrost's legacy route. Deployment, self-service persistence, and runtime attribution remain unverified; see the [verification ledger](verification.md).

The program creates a one-instance CloudNativePG database with `10Gi` storage and applies Pulumi `protect: true` to `agent-gateway-postgres`. Dedicated database workload labels propagate through CloudNativePG inherited metadata to operator-created pods. The database stores analytics and persistent standalone resources. Source protection blocks ordinary deletion or replacement; removing, replacing, or unprotecting the database still requires a separate backup/recovery and destructive authorization boundary. This tracked protection has not been exercised against live state.

`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `CHUTES_API_KEY`, and `CEREBRAS_API_KEY` seed Pulumi Stashes named `openai-api-key`, `anthropic-api-key`, `chutes-api-key`, and `cerebras-api-key`, then populate provider Secrets. When an environment variable is absent, the program passes a secret empty-string input so an existing Stash can retain its output. The program validates each resolved output before it becomes a provider Secret value. A non-empty retained output remains valid without the environment variable; an empty or blank output fails with a non-secret error that names only the corresponding environment variable. Fresh Stashes still require the corresponding credential. The program exports `routeUrl`, `uiRouteUrl`, `gateway`, `gatewayNamespace`, and `backendNames`. The gateway outputs identify `ingress/default-gateway`. These source facts do not prove a preview, deployment, or live standalone runtime.

The tracked route contract assigns the audio workloads and ordinary Gateway API HTTPRoutes to `rfhold/whisperx-server` and `rfhold/kokoro-server`. It assigns exact `/v1/audio/transcriptions` and `/v1/audio/speech` routes to workload Services through `ingress/default-gateway`. It preserves `whisperx.holdenitdown.net` and `kokoro.holdenitdown.net` as direct hostnames. Service EndpointSlices form the future-balanced backend pool as replicas increase. Homelab source renders neither audio HTTPRoute. The contract retains private-network access without gateway client authentication; workload-repository and live state remain unverified.

`routingRepresentationMode` is orthogonal to route storage. `routes` renders ten legacy `traffic.route` records and no first-class resources. With Pantheon's provider configuration, `prepare-first-class` renders all ten legacy routes plus nine `llm.provider` and eighteen `llm.model` records. `first-class` retains only Bifrost as a legacy route alongside the same providers and models. Non-`routes` modes reject any route-storage mode other than `database`. Source supports only the forward sequence `routes -> prepare-first-class -> first-class`. The parser rejects the removed `prepare-routes` mode.

Legacy-only rollback is unsupported. After runtime keys exist, a return to `routes` removes the required `llm.policies.apiKey` policy and breaks hybrid materialization. The initial `file`, `prepare-database`, and `routes` states remain available for forward migration, not rollback after first-class activation or key creation. Static parsers validate mode names and storage compatibility; they do not inspect transition history or database keys. Direct backward selection of an otherwise valid initial mode therefore remains an unsupported manual action, not a detected transition. Source provides no automatic key deletion or hidden LLM stub. In pinned v1.5, empty `llm.gateways` implicitly attaches to `default`; explicit port configuration instead creates a listener. Neither produces a policy-only stub.

Pantheon's desired `first-class` representation therefore contains Bifrost as its sole final PostgreSQL route, nine providers, and eighteen models. The provider IDs are `openai`, `anthropic`, `claude`, `chutes`, `codex`, `cerebras`, `vllm-local-embedding`, `llama-cpp-local-small`, and `llama-cpp-vulkan`. Host-derived provider `baseUrl` values stop at scheme, host, and port. OpenAI, Anthropic, Chutes, and Cerebras use literal `$ENV_VAR` placeholders, Chutes and Cerebras preserve explicit TLS SNI, and wildcard-provider defaults strip their configured prefixes.

The model set contains four wildcard families, three exact Codex aliases, the seven exact Chutes aliases, one Cerebras alias, and three local aliases. Each model ID equals its name and references its provider; exact aliases set the upstream model in `params.model`. The first-class route surface is Agent Gateway v1.5's fixed LLM route table. `/v1/models` becomes a local configured inventory, including wildcard entries, rather than an upstream provider request. Bifrost remains legacy to preserve inbound `/openai/v1/chat/completions` and `bifrost/` stripping, and it is the only UI entry represented as a Legacy Backend after `first-class` activation.

Pantheon configures `dreamer` as `gpt-6-astra`, `workhorse` as `gpt-6.1-sol`, and `turbo` as `gpt-6-luna` through provider `codex`. These match `codex/gpt-6-astra`, `codex/gpt-6.1-sol`, and `codex/gpt-6-luna`, respectively. Exact alias resources set the unprefixed upstream model in `params.model`. The provider retains its Codex Proxy endpoint and `codex/` prefix default, so `codex/*` remains available. Source does not prove that Codex Proxy serves these models; the [verification ledger](verification.md) records that runtime gap.

[`src/providers/agent-gateway`](../../src/providers/agent-gateway) implements separate Pulumi dynamic sets for `llm.provider`, `llm.model`, and `traffic.route`. Dependencies order the chart and HTTPRoute before providers, providers before models, and models before routes.

In-place updates preflight IDs newly entering Pulumi ownership. An absent ID proceeds, a canonically identical existing value is adopted, and a differing value fails before PUT or DELETE. Existing owned IDs remain Pulumi-authoritative. The provider then upserts the complete desired set and verifies every expected returned ID, kind, and canonical value before deleting removed owned IDs. Collection operations preserve unrelated records and delete only IDs removed from or previously owned by the set. Create likewise adopts canonically identical declared values, including recovery after an uncertain response, but rejects differing values without overwriting them. Resource kinds and IDs use strict URL path-segment encoding, including the slash and wildcard characters in model IDs. Each request attempt has a 10-second timeout that remains active through receipt and full response-body consumption or parsing; timeout retries remain bounded. A refreshed Pulumi update can reconcile UI edits to selected-state Pulumi IDs as drift, while undeclared IDs and kinds remain UI-owned.

Endpoint or kind changes set `deleteBeforeReplace: true`. They intentionally delete the old owned objects before creating the replacement and are not seamless endpoint migrations; an explicit preview and applicable mutation authorization are required.

The stable local aliases are `local-embedding`, mapped to `Qwen/Qwen3-Embedding-0.6B`; `local-small`, mapped to `qwen3.5-9b-hauhaucs-aggressive`; and `local-medium`, mapped to `flint`. Provider `llama-cpp-local-small` retains Service `qwen3-8-27b-llama-cpp.llama-cpp.svc.cluster.local:8000`; the historical Service name does not identify the selected model. The source also retains exact Chutes and Cerebras aliases. Prefix policies remove `openai/`, `anthropic/`, `claude/`, `codex/`, or `bifrost/` before forwarding in their owning representation. Actual provider credentials remain only in Kubernetes Secret environment variables; database resource values contain references such as `$OPENAI_API_KEY`, never the credential values. The [model gateway specification](spec/model-gateway.md) records the complete durable provider, model, transition, and split-ownership contract. Live evidence remains recorded separately in the verification ledger.

[`programs/codex-proxy`](../../programs/codex-proxy) configures a Pantheon workload with image `cr.holdenitdown.net/rfhold/codex-proxy:v2.0.76`, a persistent `/app/data` mount, disabled request-body logging, disabled automatic updates, no proxy API key or proxy IP health-check configuration, a ClusterIP Service, and an administrative HTTPRoute. Agent Gateway reaches that Service without an upstream authorization Secret.

The `rfhold/claude-proxy` repository owns the Claude Proxy namespace, workload, PVC, Service, CI, and Pulumi program. Homelab configures only the Agent Gateway backend route. That route uses the native Anthropic provider, targets `claude-proxy.claude-proxy.svc.cluster.local:8080`, removes only `claude/`, and supplies no upstream authorization Secret. The direct Anthropic provider retains its separate `anthropic/` prefix and credential.

[`src/components/vllm.ts`](../../src/components/vllm.ts) accepts optional tokenizer, maximum-batched-token, KV-cache, KV-scale, speculative-decoding, Deployment-strategy, and startup-probe settings. It emits their CLI flags only when configured and otherwise preserves existing defaults, including the default Recreate strategy and startup probe. Speculative configuration is serialized once as JSON for `--speculative-config`. The standalone vLLM program passes these settings with model, runtime, placement, resources, devices, and cache configuration. A supplied `HF_TOKEN` seeds a newly created `hf-token` Pulumi Stash. Without the environment variable, the program fails before Stash construction unless the stack explicitly sets `reuseRetainedHfToken: true`; that opt-in passes a secret empty-string input so an already-seeded immutable Stash retains its original output. Operators must enable the opt-in only after verifying that the selected stack already has that seeded Stash. A fresh stack still requires `HF_TOKEN` for initial token seeding.

Both standalone programs create and retain their configured Namespace unless `createNamespace` is explicitly false, in which case they use `Namespace.get` to reference the existing physical Namespace. The embedding stack preserves the default and owns `vllm`. The selected Mars Qwen llama.cpp stack sets `createNamespace: false` and references the shared `llama-cpp` Namespace; its retained vLLM rollback stack likewise references `vllm`.

The Mars Qwen stack pins CUDA image `ghcr.io/ggml-org/llama.cpp:server-cuda-b10630`. It selects `HauhauCS/Qwen3.5-9B-Uncensored-HauhauCS-Aggressive` file `Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-Q8_0.gguf`. The [publisher's model card](https://huggingface.co/HauhauCS/Qwen3.5-9B-Uncensored-HauhauCS-Aggressive) lists this Q8_0 artifact, a Qwen3.5-9B base, 262K context, and MTP support. The stack supports text and image inputs through `mmproj-Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-BF16.gguf` from the same repository. b10630 automatically discovers and downloads this projector through `--hf-repo` by default. Source supplies no explicit `--mmproj` argument and no projector-disable flag. The repository revision remains unpinned. This contract does not promise video support. The stack retains its historical filename, resource and Service identities, cache, and hardware allocation. Context `262144` remains shared between input and output. The selected GGUF lacks MTP layers, as confirmed by b10630 startup logs. Source omits all three MTP argument pairs; the publisher's general MTP claim does not establish artifact support. Sampling defaults remain temperature `0.6`, top-p `0.95`, top-k `20`, min-p `0`, presence penalty `0`, and repeat penalty `1`. Request-level sampling overrides remain available. Publisher refusal claims lack independent verification.

The stack passes `--jinja --reasoning on --chat-template-kwargs '{"enable_thinking":false}' --reasoning-format deepseek`. It omits fixed `--reasoning-effort xhigh` and `--reasoning-preserve`, and retains the default unrestricted reasoning budget `-1`. The pinned [b10630 request parser](https://github.com/ggml-org/llama.cpp/blob/b10630/tools/server/server-common.cpp) merges request template kwargs over server defaults. The intended request contract enables reasoning with `chat_template_kwargs: {"enable_thinking": true}` and disables it with explicit `enable_thinking: false`. Historical b10630 tests on the prior petruhonk model showed that `reasoning_effort: "none"` did not override explicit `enable_thinking: true`. That effort field alone matched the default-off behavior. Requests can add `reasoning_budget_tokens`, with `thinking_budget_tokens` as the fallback field. A budget alone does not enable reasoning under the intended contract. The HauhauCS smoke checks cover default-off output, explicit reasoning enablement, and one tool call; no effort-to-budget mapping exists in this contract. The budgeted reasoning check hit its output cap and does not establish completed reasoning or general budget enforcement. The parser retains separate `reasoning_content` output. The [verification ledger](verification.md) records the confirmed HauhauCS MTP incompatibility and limited recovery and image smoke evidence. Broader template, context, memory, completion, and performance checks remain unresolved.

The old FP8 vLLM stack retains its image, model, token-reuse configuration, and runtime settings at zero replicas for rollback. The token-reuse opt-in records the operator precondition but does not prove the Stash exists in live state. The embedding stack intentionally omits an NVIDIA GPU resource request to retain the existing Athena scheduler behavior; this source choice does not account for or formally partition GPU capacity shared with Gemma and planned speech services.

[`src/components/llama-cpp.ts`](../../src/components/llama-cpp.ts) accepts model source, server settings, placement, resources, probes, and optional host-device mappings. Its replica default preserves an explicit zero, allowing the Qwen3.6 rollback Deployment to remain scaled down. Deployments use two-hour Pulumi create and update timeouts so cold model downloads can remain inside their configured startup-probe window. Each device mapping becomes a hostPath volume and matching container mount. The program requires and stashes `HF_TOKEN` only for Hugging Face repository or file sources and supports owned or referenced Namespaces.

Both components place Hugging Face cache variables on the configured persistent model-cache volume unless a stack overrides them. The standalone programs do not render HTTPRoute or Agent Gateway resources; client routing is configured separately in Agent Gateway.

## Registry

The Pantheon container-registry stack has tracked Zot configuration enabled with an S3 backend, pull-through synchronization, a LoadBalancer Service, and `cr.holdenitdown.net` DNS annotation. Source currently disables Zot UI and search, supplies a long startup probe, and asks the registry module to create a cert-manager Certificate. Those source facts do not resolve the approval and deployment gap recorded in [verification](verification.md).
